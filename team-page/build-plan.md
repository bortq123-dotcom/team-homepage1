# 에이또팀 팀 홈페이지 제작 계획서

문서 상태: **구현 완료 · 로컬 HTTP 브라우저 확인 완료** / 작성일: **2026-11-06**

사용자의 제작 요청과 제공된 디자인 MD를 반영한 구현을 마쳤습니다. 로컬 HTTP 환경에서 데스크톱·모바일 화면과 폼 흐름을 확인했습니다. 상세 결과와 미확인 범위는 `verification.md`에 기록했습니다. 배포는 별도 진행 중입니다.

## 1. 만들 것

- 한 장짜리 에이또팀 소개 홈페이지 `index.html`. 요구사항은 `prd.md`를 따릅니다.
- 팀원이 작업계획서 작성 요청 내용을 입력하고, 검토·수정·체험 완료까지 진행하는 신청폼.
- 디자인은 사진 중심의 넓은 히어로와 극적인 글자 크기 대비를 사용합니다. UI는 `#111111`·`#FFFFFF`·`#F5F5F5`, 검정 pill 버튼과 8px 간격 리듬으로 구성합니다.
- 기존 로고는 유지하고 틸은 로고에만 남깁니다. 사진은 모서리 없이 사용하며 그림자·장식 그라데이션을 최소화합니다.
- 도구 소개는 “준비 중” 카드로 표시합니다.
- 이번 폼은 현재 화면에서 입력 흐름을 체험하는 범위입니다. 입력값은 새로고침하면 초기화되며 담당자에게 전달되지 않습니다. `(값 유지 방식 가정)`

## 2. 파일 구조

```text
team-page/
├─ prd.md             ← 디자인 참고자료 반영 요구사항
├─ logo-prompt.md     ← 생성에 사용한 최종 로고 프롬프트
├─ image-prompt.md    ← 히어로 사진 생성 프롬프트
├─ build-plan.md      ← 이 문서
├─ verification.md    ← 확인 결과와 한계
├─ index.html         ← 구현 완료, CSS·JS 포함
├─ images/
│  ├─ logo.png        ← 기존 생성 로고 유지
│  └─ hero-workplan.png ← 생성·적용 완료한 히어로 사진
└─ fonts/
   ├─ PretendardVariable.woff2 ← 로컬 글꼴
   └─ LICENSE.txt     ← SIL Open Font License
```

디자인 참고자료는 사용자 제공 `붙여넣은 텍스트.txt`입니다. 사진·글자 위계·중성 UI 원칙을 적용했습니다. 글꼴은 SIL OFL의 Pretendard를 로컬 포함하며 외부 글꼴 CDN을 사용하지 않습니다. 위 파일 구조를 유지해 더블클릭으로 여는 형태이며 실제 `file://` 브라우저 동작은 아직 확인하지 않았습니다.

## 4. 만드는 순서

| 단계 | 할 일 | 확인할 것 |
|---|---|---|
| 1 | 고정 헤더, 소개·서류·도구·요청 섹션, 푸터 작성 | 메뉴가 섹션으로 이동하고 팀 이름이 정확한지 |
| 2 | 흑백·회색 변수, 큰 제목, 8px 간격, pill 버튼과 로고 적용 | 중성 UI, 틸은 로고만 사용, 글자 위계 |

| 5 | 입력폼과 항목별 필수값 검증 구현 | 빈 값·공백·잘못된 날짜의 오류 문구와 포커스 |
| 6 | 입력 → 검토 → 수정 또는 체험 완료 → 다시 작성 구현 | 수정 시 값 유지, 검토 내용 일치, 다시 작성 시 초기화 |
| 7 | 단계 변경 안내·키보드 조작·모바일 메뉴 구현 | 화면 제목 포커스, 보조기기 안내, 375px 입력 가능 여부 |
| 8 | 데스크톱·휴대폰 화면 및 주요 폼 흐름 확인 | PRD 12번 완료 기준, 외부 전송 없음, 새로고침 시 초기화 |

## 5. 섹션별 구현 메모

| 섹션 | 레이아웃 · 내용 | 데스크톱 → 휴대폰 |
|---|---|---|
| 헤더 | 로고·팀 이름과 섹션 메뉴, 주요 이동 버튼 | 메뉴를 햄버거 버튼으로 전환 |
| 팀 소개 | 넓은 사진 히어로, 크게 대비되는 제목, 신청폼으로 가는 pill 버튼 | 가로 사진 → 세로에 가까운 크롭, 제목 크기 조절 |
| 작성 가능한 서류 | 작업계획서 카드 1개와 입력 체험 링크 | 넉넉한 단일 카드 → 화면 폭에 맞는 카드 |
| 우리가 만든 도구 | 준비 중 카드 1개 | 단일 카드 유지 |
| 작성 요청 | 단계 표시, 입력폼, 검토 내용, 완료 상태 | 넓은 화면에서도 읽기 좋은 최대 폭, 모바일 1열 |
| 푸터 | 에이또팀과 작업계획서 작성 요청 입력 체험 안내 | 짧은 문구로 줄바꿈 |

### 신청폼 상태와 값 관리

- 상태는 **입력 / 검토 / 체험 완료** 세 단계로 구성합니다.
- 폼의 값은 페이지 메모리에서만 유지합니다. 새로고침하면 빈 입력 상태로 돌아갑니다. `(가정)`
- 필수 항목은 닉네임·작업명·가상 작업구역·예정일, 요청 내용은 선택으로 제안합니다. `(가정)`
- “내용 확인”에서 검증하며, 오류가 있으면 첫 오류 항목으로 이동합니다.
- 검토 화면은 항목명과 사용자 입력을 텍스트로 표시합니다. 사용자 입력을 HTML로 삽입하지 않습니다.
- “수정하기”는 값을 유지합니다. “체험 완료”는 완료 화면으로 이동합니다.
- 완료 제목은 **입력 체험을 마쳤습니다**로 표시하고, 실제 요청이 전달되지 않았음을 함께 안내합니다.
- “다시 작성하기”는 값과 오류를 지우고 첫 입력 항목으로 이동합니다.
- 서버 호출, 메일 발송, 공용 목록, 로그인, 파일 첨부 기능을 포함하지 않습니다.

## 6. 확인 결과와 남은 범위

로컬 HTTP 환경의 **1280×900 데스크톱**과 **375×812 모바일**에서 확인했습니다. 콘솔 오류·경고는 0건입니다. 아래 점검 절차 중 직접 확인한 결과와 추가 확인 항목을 구분했습니다.

### 화면 확인

- 로컬 HTTP로 `index.html`을 열어 이미지 로드와 데스크톱·모바일 화면을 확인했습니다. 실제 `file://` 동작은 미확인입니다.
- 사진의 모서리, 제목과 본문의 크기 차이, 중성 UI, 검정 pill 버튼, 8px 간격 리듬이 참고자료의 방향과 맞는지 확인합니다.
- 기존 로고의 틸이 버튼·폼·메뉴로 확장되지 않았는지, 로고와 사진이 로컬 파일 경로로 표시되는지 확인합니다.
- 1280px와 375px에서 제목·로고·카드·입력폼이 잘리지 않는지, 가로 스크롤이 없는지 확인합니다.
- 메뉴 이동 시 고정 헤더가 제목을 가리지 않는지, 모바일 메뉴를 열고 닫을 수 있는지 확인합니다.
- 키보드로 메뉴·입력·버튼을 순서대로 조작하고 포커스가 보이는지 확인합니다.

### 폼 흐름 확인

1. 빈 폼에서 “내용 확인”을 눌러 오류 문구와 첫 오류 항목 포커스를 확인합니다.
2. 공백만 입력한 필수 텍스트가 통과하지 않는지 확인합니다.
3. 예시 값으로 입력한 뒤 검토 내용이 같은지 확인합니다.
4. “수정하기”에서 값이 유지되고 수정값이 다시 검토 화면에 반영되는지 확인합니다.
5. 선택 항목을 비워도 진행되고 “입력하지 않음”으로 표시되는지 확인합니다.
6. `<b>예시</b>` 같은 입력을 글자 그대로 표시하는지 확인합니다.
7. 체험 완료 문구와 실제 요청 미전달 안내를 확인합니다.
8. “다시 작성하기”와 새로고침에서 입력값이 초기화되는지 확인합니다.
9. 폼을 진행하는 동안 제출에 따른 외부 네트워크 요청이 없는지 확인합니다.

위 항목 중 빈 폼 오류 4개와 닉네임 포커스, 입력·검토·수정값 유지, 선택 항목 공란 허용, HTML 모양 문자 텍스트 표시, 완료 내용과 다시 작성 초기화, 모바일 예시 입력·검토·새로고침 초기화를 직접 확인했습니다. 모바일 메뉴의 첫 링크 포커스와 Escape 닫기도 확인했습니다.

스크립트 구문과 로컬 자산 검사, 외부 전송·장기 저장 API 미사용 코드 검사를 통과했습니다. 기본 폼 제출 가능성은 초기 `fieldset disabled`와 이벤트 연결 후 활성화 방식으로 보완했습니다. 이 보완의 JavaScript 비활성화 브라우저 실험은 미수행입니다. 상세 근거와 한계는 `verification.md`를 따릅니다.
